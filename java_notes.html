01 How Java Works
▼

Java achieves its famous "Write Once, Run Anywhere" promise through a clever two-step compilation process that decouples your source code from any specific machine architecture.

Two-Step Compilation

Unlike C/C++ which compiles directly to native machine code, Java uses an intermediate representation called bytecode.

Step 1 — javac (Java Compiler) ┌─────────────────┐ ┌─────────────────┐ │ HelloWorld.java │ ──────▶ │ HelloWorld.class │ │ (source code) │ javac │ (bytecode) │ └─────────────────┘ └─────────────────┘ Human-readable Platform-neutral Step 2 — JVM Execution ┌──────────────────────────────────────────────────────┐ │ JVM │ │ ┌────────────┐ ┌─────────┐ ┌────────────────┐ │ │ │ Class │──▶│Bytecode │──▶│ Interpreter │ │ │ │ Loader │ │Verifier │ │ + JIT Compiler│ │ │ └────────────┘ └─────────┘ └───────┬────────┘ │ └──────────────────────────────────────────┼───────────┘ ▼ ┌─────────────────────┐ │ Native Machine Code │ │ (OS + CPU specific) │ └─────────────────────┘

JVM Components

  • Class Loader — Loads .class files into memory, linking and initializing them.
  • Bytecode Verifier — Checks the bytecode for safety violations before execution.
  • Execution Engine — Runs the verified bytecode using an interpreter or JIT.

JIT Compiler (Just-In-Time)

The JVM starts by interpreting bytecode — executing one instruction at a time. But it profiles which code runs most frequently (hot spots) and uses the JIT compiler to translate those into optimised native machine code on the fly.

First few runs: Bytecode ──▶ Interpreter ──▶ Executed (slower) After profiling (hot methods detected): Bytecode ──▶ JIT Compiler ──▶ Native Code (cached) ──▶ Executed (fast!) Cold Code Hot Code (interpreted) (JIT-compiled, optimised)
💡

JIT Optimisations include: inlining, dead code elimination, loop unrolling, escape analysis, and branch prediction hints. This is why Java performance rivals C++ in long-running server workloads.

02Entry Point
▼

Every Java program begins execution at a single, fixed signature method. The JVM searches for this method by name and exact signature when launching an application.

public class HelloWorld {

    // ↓ The JVM's entry point — must match EXACTLY
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }

}

Anatomy of the main Signature

KeywordWhy required
publicJVM must be able to call it from outside the class.
staticJVM calls it without creating an instance — no object exists yet.
voidJVM doesn't use a return value; exit code is managed via System.exit().
mainHardcoded name the JVM looks for (by convention and specification).
String[] argsCommand-line arguments passed to the program at launch.

Why static?

When the JVM starts, no objects have been created yet — the heap is empty. A static method belongs to the class itself, not an instance, so the JVM can invoke it without needing to instantiate anything first.

ℹ️

Since Java 21, unnamed classes and instance main methods were previewed (JEP 463), allowing simpler entry points for small programs. The traditional signature remains the standard.

Command-line Arguments

public static void main(String[] args) {
    // Run: java MyApp Alice 42
    System.out.println(args[0]);  // "Alice"
    System.out.println(args[1]);  // "42"  (still a String!)
    int n = Integer.parseInt(args[1]);  // parse to int
}

Type Casting

Moving a value between types can be widening (safe, automatic) or narrowing (potentially lossy, explicit).

Widening (Implicit / Automatic — no data loss) byte ──▶ short ──▶ int ──▶ long ──▶ float ──▶ double │ char ──▶ int Narrowing (Explicit / Manual — possible data loss) double ──▶ float ──▶ long ──▶ int ──▶ short ──▶ byte 
// Widening — automatic, safe
int    i = 42;
double d = i;    // 42.0 — no cast needed

// Narrowing — explicit cast, may lose data
double pi = 3.99;
int    n  = (int) pi;    // n = 3 (truncated, not rounded!)

// Char ↔ int
char   c = 'A';
int    code = c;   // 65 — widening
char   back = (char) 66;  // 'B' — narrowing
⚠️

Narrowing truncates, it does not round. (int) 3.99 == 3, not 4. For rounding use Math.round().

Practical Examples

// Precedence in action
int a = 2 + 3 * 4;       // = 14, not 20  (* before +)
int b = (2 + 3) * 4;    // = 20          (parens override)

// Short-circuit evaluation
boolean x = false && riskyMethod();  // riskyMethod() NEVER called
boolean y = true  || riskyMethod();  // riskyMethod() NEVER called

// Ternary operator
int max = (a > b) ? a : b;

// Compound assignment
int n = 10;
n += 5;   // n = 15
n *= 2;   // n = 30

// Pre vs Post increment
int i = 5;
int pre  = ++i;   // i becomes 6, pre = 6
int post = i++;   // post = 6, then i becomes 7

// Bitwise shift (fast powers of 2)
int x2 = 1 << 3;   // 1 * 2^3 = 8
int d2 = 16 >> 2;  // 16 / 2^2 = 4
05Strings
▼

String is a class in Java (not a primitive), but it gets special treatment. Strings are immutable — once created, the character sequence they contain cannot be changed.

String Pool

The JVM maintains a special area of the heap called the String Constant Pool. String literals are interned there — two identical literals point to the same object, saving memory.

String Pool (in Heap) ┌─────────────────────────────────────┐ │ ┌──────────┐ ┌──────────────┐ │ │ │ "hello" │ │ "world" │ │ │ └─────┬────┘ └──────┬───────┘ │ └────────┼────────────────┼───────────┘ │ │ String a─┘ String b────┤ (a == b is TRUE) String c (new String("hello")) ← outside pool, == FALSE 
String a = "hello";
String b = "hello";
String c = new String("hello");

System.out.println(a == b);         // true  (same pool object)
System.out.println(a == c);         // false (new creates on heap)
System.out.println(a.equals(c));    // true  (compares content)
System.out.println(c.intern() == a); // true  (intern() looks in pool)
🚨

Always use .equals() to compare String content. Using == compares object references and will give you bugs with heap-allocated strings.

Immutability

When you "modify" a String, Java creates a new String object. The original is unchanged. This is thread-safe by nature but can be expensive in loops.

String s = "Hello";
s         = s + " World";
// A NEW String "Hello World" is created.
// "Hello" still exists in memory (until GC).

StringBuilder vs String

❌ Inefficient (in loops)

String result = "";
for (int i = 0; i < 1000; i++) {
    result += i;
    // 1000 new String objects!
}

✅ Efficient (mutable buffer)

StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(i);
}
String result = sb.toString();
💡

StringBuilder is not thread-safe (faster). StringBuffer is thread-safe (all methods synchronized). In single-threaded code, always prefer StringBuilder.

06OOP Concepts
▼

Methods & Overloading

Methods are functions that belong to a class. Method Overloading allows multiple methods with the same name but different parameter lists (resolved at compile time).

class Calculator {
    int    add(int a, int b)          { return a + b; }
    double add(double a, double b)  { return a + b; }
    int    add(int a, int b, int c)  { return a + b + c; }
    // Return type alone cannot differentiate overloads!
}

Constructors

A constructor initialises an object. It has the same name as the class and no return type.

class Person {
    String name;
    int    age;

    // 1. Default constructor (no params)
    Person() {
        this.name = "Unknown";
        this.age  = 0;
    }

    // 2. Parameterized constructor
    Person(String name, int age) {
        this.name = name;   // 'this' disambiguates
        this.age  = age;
    }

    // 3. Copy constructor
    Person(Person other) {
        this.name = other.name;
        this.age  = other.age;
    }
}

super and this

class Animal {
    String sound = "...";
    Animal(String s) { this.sound = s; }
    void speak() { System.out.println(sound); }
}

class Dog extends Animal {
    String breed;

    Dog(String breed) {
        super("Woof");       // must be first statement — calls parent ctor
        this.breed = breed;  // 'this' refers to current instance
    }

    @Override
    void speak() {
        super.speak();       // call parent method
        System.out.println("I am a " + this.breed);
    }
}

The Four Pillars of OOP

🔒 Encapsulation

Bundle data and methods together. Hide internal state with private fields and expose via public getters/setters. Protects invariants.

🧬 Inheritance

A child class (extends) inherits fields and methods from a parent. Promotes code reuse. Java supports single class inheritance only.

🎭 Polymorphism

One interface, many forms. Overloading (compile-time) and overriding (runtime). A parent reference can point to a child object.

🎨 Abstraction

Hide complexity, show only essentials. Achieved via abstract classes and interfaces. Lets you program to a contract, not an implementation.

07Key Keywords — static & final
▼

static

static means "belonging to the class, not any instance". Shared across all objects of that class.

class Counter {
    // Static variable — shared by all instances
    private static int count = 0;

    // Static block — runs once when class is first loaded
    static {
        System.out.println("Counter class loaded!");
        count = 100;  // can set initial value here
    }

    Counter() { count++; }

    // Static method — called on class, not instance
    public static int getCount() { return count; }
}

// Usage
new Counter();
new Counter();
Counter.getCount();  // 102
⚠️

Static methods cannot access instance (this) fields or methods directly. They only see other static members.

final

final means "this cannot be changed after initialisation".

// 1. Final variable — constant value, must be assigned once
final double PI = 3.14159265;
// PI = 3; ← compile error!

// 2. Final method — cannot be overridden in subclass
class Base {
    public final void seal() { System.out.println("Cannot override me"); }
}

// 3. Final class — cannot be extended (subclassed)
final class ImmutablePoint {
    final int x, y;
    ImmutablePoint(int x, int y) { this.x = x; this.y = y; }
}
// class Sub extends ImmutablePoint {} ← compile error!

// Static + final = class constant (convention: UPPER_SNAKE_CASE)
public static final int MAX_SIZE = 1024;
ℹ️

Note: final on a reference variable means the reference cannot be reassigned, but the object it points to can still be mutated (e.g., adding to a final List is allowed).

08Polymorphism & Abstraction
▼

Compile-time Polymorphism

Also called static dispatch. Resolved by compiler based on the method signature (parameter types/count).

  • Method overloading
  • Operator overloading (limited in Java)

Runtime Polymorphism

Also called dynamic dispatch. The JVM decides at runtime which method to call based on the actual object type.

  • Method overriding
  • Requires inheritance + @Override
class Shape {
    double area() { return 0; }
}
class Circle extends Shape {
    double r;
    Circle(double r) { this.r = r; }
    @Override double area() { return Math.PI * r * r; }
}
class Square extends Shape {
    double s;
    Square(double s) { this.s = s; }
    @Override double area() { return s * s; }
}

// Runtime polymorphism in action:
Shape[] shapes = {new Circle(5), new Square(4)};
for (Shape sh : shapes)
    System.out.println(sh.area());  // JVM picks correct area() at runtime

Abstract Classes

An abstract class cannot be instantiated. It can have a mix of fully implemented and abstract (signature-only) methods, forcing subclasses to provide implementations.

abstract class Vehicle {
    String brand;

    // Concrete method — inherited as-is
    void start() { System.out.println(brand + " starting..."); }

    // Abstract method — MUST be overridden by subclass
    abstract void fuelType();
}

class Car extends Vehicle {
    @Override void fuelType() { System.out.println("Petrol"); }
}
// new Vehicle(); ← compile error!
Vehicle v = new Car();  // OK via polymorphism

When to use Abstract Class?

  • You want to share code (concrete methods) between related classes.
  • You need constructors, instance fields, or protected members.
  • You're modelling an "is-a" relationship with a partial implementation.
  • You want to enforce a template pattern (some methods defined, some deferred).
09Interfaces
▼

An interface is a pure contract. It defines what a class can do, not how it does it. A class implements an interface and must provide implementations for all abstract methods.

interface Drawable {
    // 1. Abstract method (implicit public abstract)
    void draw();

    // 2. Default method (Java 8+) — provides a default implementation
    default void describe() {
        System.out.println("I am drawable!");
    }

    // 3. Static method (Java 8+) — called on the interface itself
    static void info() {
        System.out.println("Drawable interface v1.0");
    }

    // 4. Constant (implicit public static final)
    int VERSION = 1;
}

// Multiple interface implementation
interface Resizable { void resize(double factor); }

class Rectangle implements Drawable, Resizable {
    double w, h;
    @Override public void draw()                    { System.out.println("□"); }
    @Override public void resize(double f)           { w *= f; h *= f; }
}

10Inner Classes
▼

Java allows defining a class inside another class. There are 4 types, each with different scoping rules.

1. Member (Non-static) Inner Class

Defined inside a class, not in a method. Has access to all outer class members (even private). Requires an outer instance to create.

class Outer {
    private int x = 10;

    class Inner {
        void show() { System.out.println(x); }  // accesses outer x
    }
}
// Usage:
Outer o       = new Outer();
Outer.Inner i = o.new Inner();

2. Static Nested Class

Declared with static. Cannot access outer class instance members (only static ones). Does NOT need outer instance.

class Outer {
    static int y = 20;

    static class Nested {
        void show() { System.out.println(y); }
    }
}
// Usage: no outer instance needed
Outer.Nested n = new Outer.Nested();

3. Local Inner Class

Defined inside a method. Only accessible within that method. Can access effectively final variables from the enclosing method.

void myMethod() {
    int val = 42;  // effectively final

    class Local {
        void print() { System.out.println(val); }
    }
    new Local().print();
}

4. Anonymous Inner Class

A one-time-use class with no name. Declared and instantiated in a single expression. Commonly used to implement interfaces or extend abstract classes on the fly. (Largely replaced by lambdas in Java 8+.)

// Anonymous class implementing Runnable
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("Running anonymously");
    }
};
r.run();

// Equivalent lambda (Java 8+)
Runnable r2 = () -> System.out.println("Running with lambda");

Overriding toString, equals, hashCode

class Point {
    int x, y;
    Point(int x, int y) { this.x = x; this.y = y; }

    @Override
    public String toString() {
        return "Point(" + x + ", " + y + ")";
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Point)) return false;
        Point p = (Point) o;
        return this.x == p.x && this.y == p.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);  // must be consistent with equals
    }
}
⚠️

Contract: If two objects are equals(), they MUST have the same hashCode(). Violating this breaks HashMap, HashSet, etc.

12Exception Handling
▼

An exception is an event that disrupts normal program flow. Java uses a hierarchical exception class system rooted at Throwable.

java.lang.Throwable ├── Error (JVM problems — don't catch) │ ├── OutOfMemoryError │ └── StackOverflowError └── Exception ├── IOException ← Checked ├── SQLException ← Checked ├── RuntimeException ← Unchecked │ ├── NullPointerException │ ├── ArrayIndexOutOfBoundsException │ ├── ClassCastException │ └── IllegalArgumentException └── ...

Checked vs Unchecked

Checked Exceptions

  • Subclass of Exception (not RuntimeException)
  • Must be declared with throws or caught
  • Compiler enforces handling
  • Examples: IOException, SQLException

Unchecked Exceptions

  • Subclass of RuntimeException
  • Compiler does NOT enforce handling
  • Usually programmer mistakes
  • Examples: NullPointerException, ClassCastException

try-catch-finally

try {
    int result = 10 / 0;  // throws ArithmeticException
    int[] arr = new int[3];
    arr[10] = 5;              // throws ArrayIndexOutOfBoundsException

} catch (ArithmeticException e) {
    System.out.println("Math error: " + e.getMessage());

} catch (ArrayIndexOutOfBoundsException | NullPointerException e) {
    // Multi-catch (Java 7+)
    System.out.println("Array/Null issue: " + e);

} finally {
    // ALWAYS runs — even if exception or return statement!
    System.out.println("Cleanup here");
}

// try-with-resources (Java 7+) — auto-closes Autocloseable
try (FileReader fr = new FileReader("file.txt")) {
    // fr.close() is called automatically
} catch (IOException e) {
    e.printStackTrace();
}

throw vs throws

throw

Used to actually throw an exception object in your code.

throw new IllegalArgumentException("Bad input");

throws

Declares that a method might throw a checked exception.

void readFile() throws IOException {...}

Custom Exceptions

// Custom checked exception
class InsufficientFundsException extends Exception {
    private double amount;

    InsufficientFundsException(double amount) {
        super("Insufficient funds: needed " + amount);
        this.amount = amount;
    }
    public double getAmount() { return amount; }
}

// Custom unchecked exception
class ValidationException extends RuntimeException {
    ValidationException(String msg) { super(msg); }
}

Integer a = 127;

Integer c = 128;
Integer d = 128;
System.out.println(c == d);    // FALSE — new objects outside cache range
System.out.println(c.equals(d));  // TRUE  — always use .equals() for wrappers!
⚠️

14Multithreading
▼

A thread is the smallest unit of CPU execution. Multithreading allows concurrent execution of two or more threads, enabling better CPU utilisation and responsiveness.

Thread Lifecycle

┌──────────┐ start() ┌─────────┐ scheduler ┌─────────┐ │ NEW │ ─────────▶ │RUNNABLE │ ──────────▶ │RUNNING │ └──────────┘ └─────────┘ └────┬────┘ ▲ │ │ notify() / │ wait() / sleep() │ timeout │ join() / I/O block │ ▼ ┌────┴─────┐ ┌──────────────┐ │ BLOCKED │◀──────────│ WAITING │ │ (lock) │ │ TIMED_WAIT │ └──────────┘ └──────────────┘ │ run() ends / exception ▼ ┌────────────┐ │ TERMINATED │ └────────────┘

Creating Threads — Two Ways

Way 1: Extend Thread

class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println(
          "Thread: " +
          Thread.currentThread().getName());
    }
}
MyThread t = new MyThread();
t.start();  // not t.run()!

Way 2: Implement Runnable ✅ preferred

class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Task running");
    }
}
Thread t = new Thread(new MyTask());
t.start();

// With lambda:
new Thread(() ->
    System.out.println("Lambda thread"))
    .start();

15Synchronization & Locks
▼

Race Condition

When multiple threads read and write shared data concurrently, the outcome depends on thread scheduling — producing unpredictable results.

class Counter {
    int count = 0;  // shared state — DANGEROUS

    void increment() {
        count++;  // NOT atomic: read → add 1 → write (3 steps!)
    }
}
// Two threads running increment() 1000x may NOT give count = 2000

synchronized keyword

Uses the object's intrinsic lock (monitor). Only one thread can hold the lock at a time.

// 1. Synchronized instance method — lock on 'this'
synchronized void increment() {
    count++;  // now thread-safe
}

// 2. Synchronized static method — lock on the Class object
static synchronized void staticMethod() { ... }

// 3. Synchronized block — finer-grained lock (preferred)
void increment() {
    // do non-critical work here...
    synchronized (this) {  // or any shared object
        count++;
    }
    // do non-critical work here...
}

ReentrantLock Example

import java.util.concurrent.locks.ReentrantLock;

class SafeCounter {
    private int count = 0;
    private final ReentrantLock lock = new ReentrantLock();

    void increment() {
        lock.lock();
        try {
            count++;
        } finally {
            lock.unlock();  // ALWAYS in finally!
        }
    }
}

ReadWriteLock

Allows multiple threads to read simultaneously, but only one thread to write. Greatly improves read-heavy scenarios.

ReadWriteLock rwLock = new ReentrantReadWriteLock();
Lock readLock  = rwLock.readLock();
Lock writeLock = rwLock.writeLock();

// Multiple readers OK simultaneously
readLock.lock();
try { /* read shared data */ }
finally { readLock.unlock(); }

// Only one writer at a time, no readers allowed
writeLock.lock();
try { /* modify shared data */ }
finally { writeLock.unlock(); }

Deadlock

Deadlock occurs when two or more threads are blocked forever, each waiting for a lock the other holds.

Thread-1 holds Lock A, waiting for Lock B ─────┐ ↕ DEADLOCK Thread-2 holds Lock B, waiting for Lock A ─────┘ 
// Classic deadlock scenario
synchronized(lockA) {
    Thread.sleep(100);
    synchronized(lockB) { /* Thread-1 waits here */ }
}
// Thread-2 acquires lockB first, then tries lockA — DEADLOCK!

// FIX: always acquire locks in the SAME ORDER
synchronized(lockA) {
    synchronized(lockB) { /* both threads use A→B order */ }
}

Thread Communication — wait() / notify()

class SharedBox {
    private int value;
    private boolean hasValue = false;

    public synchronized void put(int v) throws InterruptedException {
        while (hasValue) wait();  // release lock, wait for consumer
        this.value = v; hasValue = true;
        notifyAll();  // wake waiting threads
    }

    public synchronized int get() throws InterruptedException {
        while (!hasValue) wait();  // wait for producer
        hasValue = false;
        notifyAll();
        return value;
    }
}
💡

Always use while (not if) with wait() to guard against spurious wakeups — threads can be woken without notify() being called.

16Lambda Expressions
▼

Lambdas (Java 8+) provide a concise way to implement functional interfaces — interfaces with exactly one abstract method. They enable functional-style programming in Java.

Syntax

(parameters) -> expression (parameters) -> { statements; } Examples: () -> System.out.println("hi") // no params x -> x * x // one param (parens optional) (x, y) -> x + y // two params (x, y) -> { int s = x+y; return s; } // block body

Functional Interface

Any interface with exactly one abstract method is a functional interface. The @FunctionalInterface annotation is optional but recommended — it makes the compiler enforce the single-method rule.

@FunctionalInterface
interface Transformer {
    int transform(int x);
}

// Anonymous class way (verbose)
Transformer square1 = new Transformer() {
    @Override public int transform(int x) { return x * x; }
};

// Lambda way (concise)
Transformer square2 = x -> x * x;

System.out.println(square2.transform(5));  // 25

17Thread Pooling & Executors
▼
ℹ️

Why Thread Pools? Creating a new Thread object is expensive (OS resources). Submitting 1000 tasks that each spawn a thread would overload the system. Thread pools reuse a fixed set of worker threads — submit tasks, workers execute them, threads stay alive for the next task.

ExecutorService

The ExecutorService interface abstracts thread management. You submit tasks; the pool handles scheduling.

ExecutorService Usage

import java.util.concurrent.*;

ExecutorService pool = Executors.newFixedThreadPool(4);

// submit(Runnable) — fire and forget
pool.submit(() -> System.out.println("Task 1 running"));

// submit(Callable) — returns a Future
Future<Integer> future = pool.submit(() -> {
    Thread.sleep(1000);  // simulate work
    return 42;
});

// future.get() blocks until result is ready
try {
    int result = future.get(2, TimeUnit.SECONDS);  // timeout
    System.out.println("Result: " + result);
} catch (TimeoutException e) {
    future.cancel(true);
}

// Always shut down to release threads
pool.shutdown();             // no new tasks, finish queued ones
pool.awaitTermination(5, TimeUnit.SECONDS);
// pool.shutdownNow();  // interrupt running tasks immediately

ScheduledExecutorService

ScheduledExecutorService sched =
    Executors.newScheduledThreadPool(2);

// Run once after 3-second delay
sched.schedule(() -> System.out.println("delayed"),
    3, TimeUnit.SECONDS);

// Run every 1 second, starting after 0-second delay
sched.scheduleAtFixedRate(() ->
    System.out.println("tick"),
    0, 1, TimeUnit.SECONDS);

// Run with 1-second GAP after previous completes
sched.scheduleWithFixedDelay(() ->
    System.out.println("tock"),
    0, 1, TimeUnit.SECONDS);
